# 地址样本配对实验协议

## 目标

在同一批地址上比较人工地图搜索与工具搜索，检验效率、结果一致性和错误合规风险。

## 前置冻结

- 固定版本：`app_version=0.4.0`、`rule_version=commute-r1.0`。
- 固定地图来源、网络环境和测试设备。
- 只使用匿名编号，真实地址清单保存在不提交的 `local-data/`。
- 先写下指标定义，再开始测试；中途不因结果好坏更改分母。

## 单例步骤

1. 为地址分配 `CASE-001` 格式编号并记录日期、时段。
2. 按奇偶编号决定人工 / 工具先后顺序。
3. 人工搜索：计时，记录尝试路线次数、最优时间、是否找到合规方案。
4. 工具搜索：选择 `self_test` 环境，记录自动生成的 request_id、用时和 Top-1。
5. 回地图 App 复核 Top-1，记录一致 / 偏短 / 偏长、站点错误、别名有效、截图可用、最终无合规。
6. 在实验表保存配对数据；备注不写完整地址。

## 计算

- 实时搜索成功率 = 实时返回路线的 CASE / 全部 CASE。
- 人工一致率 = 工具最优与人工复核结论一致的 CASE / 全部 CASE。
- Top-1 有效命中率 = Top-1 经复核有效的 CASE / 全部 CASE。
- 平均 / 中位分钟差 = `|工具最优分钟 - 人工最优分钟|`。
- 任务耗时变化 = 人工用时 - 工具用时；正数表示节省。
- 错误合规案例 = 系统判合规但地图复核后无合规方案的 CASE。
- P50/P95 延迟来自相同环境的 `search_completed.latency_ms`。

## 停止与结论规则

首批完成 20 个独立 CASE 后再写阶段性结论。少于 20 个时必须显示“样本量较小，仅用于探索性验证”。即使达到 20 个，也只描述本批地址，不外推用户总体。
