# 部署与试用说明

## 1. 当前是否可以部署到腾讯云

可以。

但应把当前版本定义成：

- 朋友试用版
- 小流量公网试用版

而不是正式生产版。

## 2. 当前最小部署前提

### 2.1 服务器要求

- 一台 Linux 云服务器
- Python 3 可用
- 能出网访问高德开放平台

### 2.2 必要环境变量

- `COMMUTE_PROVIDER_MODE=live`
- `COMMUTE_SERVER_HOST=0.0.0.0`
- `COMMUTE_SERVER_PORT=8000`
- `AMAP_WEB_KEY`

百度和腾讯 key 可以留着，但首版真实路径主力仍是高德。

## 3. 最小启动命令

```bash
cd /path/to/ai
COMMUTE_PROVIDER_MODE=live \
COMMUTE_SERVER_HOST=0.0.0.0 \
COMMUTE_SERVER_PORT=8000 \
AMAP_WEB_KEY="your-amap-key" \
BAIDU_WEB_KEY="your-baidu-key" \
QQ_MAP_KEY="your-qq-key" \
python3 backend/server.py
```

## 4. 试用前必须做的云侧配置

### 4.1 安全组

开放：

- `8000`，如果你打算直接公网访问

或者：

- `80 / 443`，如果前面挂 Nginx

### 4.2 域名和 HTTPS

朋友试用阶段：

- 可以直接用 `http://公网IP:8000`

更稳妥的方式：

- 域名
- Nginx
- HTTPS

## 5. 推荐的试用部署方式

### 方案 A：最快试用

- 直接在服务器上跑 Python 服务
- 直接开放 `8000`

优点：

- 最快

缺点：

- 不够正式
- 没有 HTTPS

### 方案 B：稍正式

- Python 服务监听 `127.0.0.1:8000`
- Nginx 对外监听 `80/443`
- Nginx 反代到 Python 服务

优点：

- 更接近正式服务
- 更适合给朋友分享

## 6. 试用前建议补的非阻塞项

### 6.1 高优先级

- 接入进程守护，例如 `systemd`
- 开启 Nginx 反向代理
- 确认高德 key 配额充足

### 6.2 中优先级

- 增加请求日志
- 增加错误日志
- 增加简单缓存
- 保护 metrics 接口 token，并限制只给内部查看

### 6.3 低优先级

- 增加分享短链
- 增加反馈入口

## 7. 当前不建议直接大规模公开的原因

- 服务端不是高并发架构
- 地图配额容易成为瓶颈
- 真实搜索策略还在调整阶段
- 还没有完整可观测性

## 8. 作者自测建议

建议先完成 20 个匿名 CASE 的配对地址样本，作者本人重点复核：

- 搜索结果是否比自己手搜更好
- `北门 / 西塔 / 栋` 比较是否有帮助
- 截图清单是否好用
- 哪些地址仍然“明明高德能搜更短，工具没有搜出来”

这些自测证据会决定下一轮产品迭代方向，不表述为真实用户反馈。

## 9. 当前埋点能力

已支持的轻量埋点（默认看板仅 `self_test,prod`）：

- 搜索总次数
- 有结果 / 无结果
- 系统找到路线次数与系统合规次数（分开）
- alias 方案命中次数
- live 失败次数
- 最优模板、结果复核、错误合规、P50/P95 延迟和匿名实验汇总

当前埋点默认不保存完整地址原文，只保存脱敏后的哈希与统计字段。
